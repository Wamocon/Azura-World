## 1. The media, and the one file that could not be committed

134 assets were produced. **133 were committed. One was not, and the reason
turned out to matter more than the file.**

`.githooks/pre-commit` rejected `azura-film.mp4` at 17 MB: *"Evidence and media
belong under git-ignored sources/."* The first instinct was to treat that as a
size problem and reach for a CDN or Git LFS. That would have been wrong.

`MEDIA-LICENSE.md` §4 is titled **"Video — referenced, never rehosted"** and says
outright: *"No video file is downloaded."* `MEDIA_ALLOW_VIDEO_DOWNLOAD` defaults
to `false`. It names downloading and rehosting a promotional film as the single
highest-risk action in the media pipeline and concludes *"only embedding is on
the table."* `media-manifest.ts` has carried `rehosted: false` on
`MediaVideoRef` since W0-D wrote it.

So the hook and the licence agreed with each other, and **the publish script was
the thing that was wrong** — it copied the film into `public/media`, which both
rehosts it and ships it. Fixed at the source rather than worked around:

- `publish-journey-media.mjs` copies only the poster frame, 70 KB, a still we
  extracted ourselves.
- `JourneyVideo.src` is typed `null`, not `string`. The contract is in the type,
  not in a comment.
- `journey-media-guard.mjs` checked *"video file present"*, which would have
  failed for the correct behaviour. It now checks the two things that are
  actually required: `src` is null, and the poster is published.

`--no-verify` was available and was not used. OVERNIGHT-2 §6 forbids it, and in
this case the hook was right for a reason better than the one it stated.

**133 published:** 66 AVIF + 74 WebP across three widths (800/1200/1600), 48
promoted to the journey, AVIF first in every `<picture>` source order.
`public/contact-sheet.html` renders all of them at thumbnail size with
provenance and dimensions. It is not linked from the app; it exists so a human
can look at 133 files at once and notice the one that is wrong, which no
automated check does.

## 6. `ProvenanceValue` → `InventoryValue`

`components/azura/inventory-value.tsx`. It takes the **same `SourcedFact`** and
renders the value and nothing else.

Wrapping the fact rather than taking a number is deliberate. PIVOT §5 is
explicit that this is pass one of two: pass one removes what the client can see
and leaves `SourcedFact` compiling, pass two unwraps the types after the pitch
with a green suite. Taking the same shape made the change **a rename at every
call site rather than a data migration**, and it keeps `formatFactValue` as the
single formatter — so `76.000 m²` is rendered by the same code in both passes.
Two formatters would drift, and the drift would show as one number written two
ways on one page.

One difference from `ProvenanceValue`: a gap renders `Keine Angabe`, not an em
dash. W-UX §3 removed that rule for the reason that applies here too.

## 10. One thing worth flagging about this worktree

**A second process is writing in `D:\azura-cinema2`, and it is confirmed, not
suspected.**

Three files changed *after* the media commit and before I touched them —
`lib/journey-media.ts`, `scripts/publish-journey-media.mjs` and
`scripts/journey-media-guard.mjs` — and the 17 MB mp4 was removed from
`public/media` at the same time. The pre-commit hook only scans and does not
edit, so something else wrote them.

Then `762721f INTERNAL-107 W-CINEMA: handoff, STATUS PARTIAL` landed **between
this window's second and third commits**, writing `HANDOFF/W-CINEMA.md`.

Nothing was lost in either direction: the edits were the non-rehosting fix in
§1, they were verified against `MEDIA-LICENSE.md` §4 and the manifest's
`rehosted: false` before being committed rather than taken on trust, and the
handoff commit touched a file this window never opened.

Two consequences worth carrying forward:

1. `CLAUDE.md` §3 says exactly one window writes any given file, and that is not
   currently true here. The next window to open in this worktree should check
   `git log` before assuming the tree is its own.
2. **`HANDOFF/W-CINEMA.md` and this file both describe this worktree** and were
   written by different passes without seeing each other. Where they disagree,
   check the commit dates. `W-CINEMA.md` is `STATUS: PARTIAL` and predates the
   pivot entirely, so its section list, its copy examples and its 254.9 KB
   budget are all pre-pivot; the section list in particular is now wrong,
   because the evidence band it describes no longer exists.
